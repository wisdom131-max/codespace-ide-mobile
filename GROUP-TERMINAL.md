# Terminal / Proot: fresh source-only group audit

**State:** app, vendored termux stack, and backend source read; no device test run. `READ A/path:N` is 1-based in `android/app/src/main/java/com/codespace/ide/`, `READ T/path:N` is 1-based in `android/app/src/main/java/com/termux/`, and `READ V/path:N` is 1-based in `vscode-src/` (repo root `src/vs/`); backend files are cited as `READ B/path:N` relative to `backend/`. This group owns the Ubuntu proot runtime end to end: rootfs download/extract/bake (`terminal/ProotInstaller.kt`), one-shot command execution (`execOnce*`), the foreground service and session lifecycle (`terminal/TerminalService.kt`, `TerminalSessionStore.kt`), the vendored PTY/emulator stack (`com/termux/terminal/`, `com/termux/view/`), the terminal UI (`ui/panes/TerminalPane.kt`), the ide CLI + OSC bridge (`terminal/IdeTerminalBridge.kt`), the AI bridges (`AgentApiServer.kt`, `McpShellProfile.kt`, `TerminalAiBridge.kt`), backup (`terminal/BackupManager.kt`), the remote terminal pair (`RemoteTerminalSession.kt` + `backend/src/terminal/terminal.gateway.ts`), and the device-compat/expansion helpers. SCM's proot spawn count (SG07), the debugger's terminal provider (DG04), and Problems' BuildRunner (PR01/PR03) are boundaries referenced, not re-audited. Nothing here is a device outcome or a code-fix authorization.
