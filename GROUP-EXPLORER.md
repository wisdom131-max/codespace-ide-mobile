# Explorer: fresh source-only group audit

**Status:** source inspected, device checks unverified. This group owns Explorer tree, file actions and Explorer-launched viewers. Search, tabs, Git execution, debugger, LSP, AI generation and project creation receive their own deeper groups. `READ A/...:N` is a 1-based line in `android/app/src/main/java/com/codespace/ide/`; `READ V/...:N` is a 1-based line in the checked-out sibling `vscode-src/src/vs/` tree. A UI entry is not proof it works on a device. Nothing in this document is a device pass/fail or an authorized code fix. Destructive checks are **DATA-RISK: scratch project only**.

## Gaps to carry into the master register

| Gap | Priority | Code evidence, bounded conclusion |
|---|---|---|
| EX01 | HIGH | `WorkspaceManager.moveToTrash` ignores `renameTo` result but returns `TrashEntry` anyway; single Delete does not verify, multi Delete increments `moved` unconditionally. Can report a successful move even when source stayed put. READ A/util/WorkspaceManager.kt:202-213; A/ui/panes/ExplorerPane.kt:2450-2470,2487-2500. |
| EX02 | HIGH | `listTrash` reconstructs `originalPath` from trashed basename, explicitly losing original nested directory; `restoreFromTrash` then targets project root. A second `_restored` collision is not iteratively disambiguated. READ A/util/WorkspaceManager.kt:215-244. |
| EX03 | MEDIUM | Cut/Paste ignores `renameTo` Boolean, then clears clipboard and refreshes; directory Copy uses nonrecursive `File.copyTo`; rename callback is not invoked for Cut/Paste. READ A/ui/panes/ExplorerPane.kt:1631-1653; A/ui/screens/ProjectShellScreen.kt:1422-1430. |
| EX04 | HIGH, containment | New File, New Folder and Rename accept nonblank names after only stripping backticks/NUL; `File(parent,nameInput)` has no canonical-in-root check. Relative separators or `..` can address a path outside the chosen folder. This is a source-level path-containment risk, not a device exploit report. READ A/ui/panes/ExplorerPane.kt:2146-2299,2302-2334. |
| EX05 | HIGH, containment | ZIP Extract Here tests `canonicalOut.startsWith(canonicalDir)` without requiring `canonicalDir + separator`. A sibling whose name begins with the output directory name passes the prefix check (e.g., `out` vs `out2`). No untrusted archive should be opened in a real project before containment is fixed. READ A/ui/panes/ExplorerPane.kt:1737-1778. |
| EX06 | MEDIUM | New Folder calls `mkdirs()` but emits `Created folder` without checking its Boolean result. READ A/ui/panes/ExplorerPane.kt:2260-2296. |
| EX07 | HIGH, destructive scope | Cloned-root `Remove & delete files` performs recursive deletion after a depth-of-three path check, not a canonical membership check against an allowed disposable/project directory. Explicit user choice is required but the guard is shallow. READ A/ui/panes/ExplorerPane.kt:1162-1211. |
| EX08 | MEDIUM | Multi-select `All` starts from `workspaceRoot` (currently displayed root), excludes internal paths even with Show hidden on, and can append previously selected files again. Its displayed count may not represent unique paths. READ A/ui/panes/ExplorerPane.kt:833-854. |

**Boundary:** project deletion/trash, find-in-files/search results, Git staging/history, full media decoder behavior, terminal mapping, AI generation transport and every LSP action are only identified here where Explorer routes to them. Their underlying feature verification belongs to their respective groups. No code fix was performed.
